# 저장과 불러오기

## 사용법

시작 화면의 오른쪽 목록에서 저장된 게임을 불러온다. 이어하기 버튼은 제거했다. 마을 아래의 `저장 / 불러오기` 버튼으로 같은 목록을 열 수 있다. 8개 슬롯을 제공하며 목록 위에서 마우스 휠로 세로 스크롤한다. 빈 슬롯과 손상된 슬롯은 불러올 수 없다. 기존 슬롯은 저장 버튼을 두 번 눌러 덮어쓰기를 확인한다. 닫았다 다시 열면 확인이 초기화된다.

저장은 마을에서 가능하며, 불러오면 마을로 돌아온다. 전투 중 몬스터·검기·경과 시간은 저장하지 않는다. 불러오기를 실행하면 현재 저장하지 않은 진행은 교체된다. 설정 창의 음량·전체 화면은 이 게임 진행 저장의 대상이 아니다.

## 저장 내용

- 벼, 골드, 특수 자원
- Day, 당일 총 수확량, 남은 횟수, 남은 수확량, 회당 수확량
- 현재 건물 종류·위치·강화 단계·시작 건물 여부
- 철거 후에도 유지되는 누적 구매 횟수
- 병력 배치 순서와 출전/대기 구분

## 코드 구조

`GameSave.cs`의 SaveData는 JSON으로 옮길 값만 담는다. GameSave는 슬롯 UI, 파일 입출력, 씬 이동을 담당한다. 건물·병력 데이터는 Inspector의 Definitions 목록에서 에셋 GUID 기반 고정 ID와 실제 ScriptableObject를 연결한다. 이름이 바뀌어도 저장 데이터가 유지되며 빌드 실행 중 AssetDatabase를 사용하지 않는다. ID는 기존 저장을 유지하려면 변경하면 안 된다.

`BuildingSave.cs`와 `RecruitmentSave.cs`는 기존 컨트롤러의 partial 구현이다. 별도 컴포넌트를 붙이는 파일이 아니라 동일 클래스의 저장 관련 코드를 분리한 것이다. CaptureSave는 현재 값을 복사하고 RestoreSave는 비용 차감 없이 상태를 재구성한다. 공용 ScriptableObject의 밸런스 수치는 덮어쓰지 않는다.

RiceHarvest의 초기화 뒤에 저장된 수확 상태를 복구해 무료 수확 초기화를 막는다. 병력은 준비 씬을 열 때 지연 복원한다. 준비 씬을 아직 열지 않은 상태에서 다시 저장해도 미복원 병력 목록을 보존한다. 편성 자리가 줄어들면 초과 병력은 대기로 보존한다. 새 게임을 시작하면 이전 불러오기 대기 데이터는 초기화한다.

파일 위치는 `Application.persistentDataPath/Saves/slot-N.json`이다. Directory Name은 Inspector에서 지정한다. 파일 버전과 기본 값·정의 참조를 검사하고 손상된 파일은 UI에서 비활성화한다. 임시 파일을 모두 쓴 뒤 원본을 교체하여 쓰기 실패 시 기존 파일을 보존한다. 암호화·클라우드 동기화·이전 스키마 마이그레이션은 구현 범위에 포함되지 않는다.

## 검증 (2026-09-22)

실제 JSON 파일 저장 및 씬 재로드 후 Day 3, 벼 999924, 골드 1234, 특수 자원 7, 남은 수확 횟수 3과 수확량 75, 건물 레벨 3 및 구매 횟수 2 복원을 확인했다. 출전 1명·대기 1명을 복원했고 준비 씬을 열기 전/후 재저장에서도 두 병력이 유지되었다. 기존 파일의 첫 저장 클릭에서는 파일이 바뀌지 않았다. 손상된 JSON은 불러오기 버튼이 비활성화되었다. ScrollRect에 휠 이벤트를 전달해 스크롤 이동을 확인했다. 실제 물리 마우스 조작이나 독립 실행 빌드 재시작 테스트는 하지 않았다.

테스트 파일은 프로젝트 `output/save-tests`에 분리하여 사용자 저장 슬롯을 사용하지 않았다. 시작 화면과 마을 저장 패널을 캡처했고 Unity 콘솔 오류·경고는 없었다.

## 시작 화면 변경
이어하기 버튼을 복원했다. 저장 슬롯 목록은 처음에는 숨겨져 있으며 이어하기를 누르면 열리고 닫기로 숨길 수 있다. 위의 이어하기 제거 설명은 이 변경으로 대체한다. 기존 GameSave.Open/Close를 버튼 이벤트에 Inspector로 연결했으며, 초기 숨김 및 열기/닫기 콜백을 검증했다.
