## 현재 상태와 주의점
- 사용자 Inspector 설정으로 **Starting Rice = 999999**. 임의로 320으로 되돌리지 않는다.
- 마을의 기존 벼 표시와 카드 가격은 수동 문구다. 실제 비용 데이터를 바꾸면 카드 문구도 직접 수정해야 한다.
- Scene Travel은 항상 활성 상태여야 하며 Village Roots 배열에 자기 자신을 넣지 않는다.
- PlayScene 직접 실행 시 마을 자원 정보가 없어 벼는 ‘—’, 고용은 잠금. 정상 테스트는 VillageScene에서 시작한다.
- StartScene은 기본 버튼 배치만 있으며 게임 흐름 연결은 미완성. 빌드 목록은 SampleScene, PlayScene, VillageScene이며 시작 순서는 변경하지 않았다.
- 디스크 저장/불러오기, 전투·이동, 생산·수확, 강화, 해고, 막사에 따른 편성 상한 확장, 시작 건물·병사 자동 지급은 아직 미구현. 실행 종료 시 상태 초기화.

## 2026-09-14 갱신: 시작 건물
VillageScene > Buildings에 Starting Farm, Starting Workshop(병영), Starting Castle(막사)을 각 1개씩 미리 배치했다. Building System > Starting Buildings에서 정의와 씬 오브젝트를 연결한다. 위치는 각 오브젝트 Transform에서 직접 변경 가능하다. 비용 차감 없이 시작하며 병사 고용이 즉시 해금된다. 시작 건물은 추가 구매 횟수에 포함하지 않아 첫 추가 Farm 비용 120을 유지한다. 겹침 방지 콜라이더도 적용했다. 씬 왕복 시 중복 생성 없음과 고용 해금을 검증했다. 이전 문서의 '빈 마을/시작 건물 미구현' 설명은 이 내용으로 대체한다. 시작 병사 자동 지급은 여전히 미구현이다.

## 2026-09-14 갱신: 그리드 건설
건물 자식 모델만 이동되어 충돌 박스와 외형이 어긋난 문제를 수정했다. 이제 건설 판정은 물리 OverlapBox 대신 점유 칸 HashSet을 사용한다. Grid Size=2, 36x36 바닥은 18x18칸이다. 건물 footprint X/Z를 칸 크기로 나누어 올림한 수만큼 점유한다(Farm 4x4, Castle 5x5). 시작 건물은 Awake에서 정렬·점유 등록하고, 신규 건물은 확정 후 점유한다. 구매 횟수/해금 규칙은 유지했다. 건물 선택 중에만 그리드 선을 표시한다.
시작 건물 위치를 바꿀 때는 Buildings 아래 Starting Farm/Workshop/Castle 부모를 이동하고 자식 모델은 움직이지 않는다. 모델 보정은 BuildingDefinition에서 관리한다. 현재 평평한 축 정렬 사각 바닥을 기준으로 하며, 별도 장애물이나 철거/이동 기능의 칸 해제는 아직 구현하지 않았다.
8종 스냅 일관성, 시작/신규 건물 겹침 차단, 인접 빈칸 건설, 경계 안/밖, 비용 차감을 실행 중 메서드 호출로 검증하고 화면 확인 및 콘솔 오류 없음 확인했다.

## 2026-09-14: 건물 이동
지어진 건물을 클릭하면 이동 모드, 빈 그리드 클릭으로 확정한다. 우클릭/Esc/건설 메뉴 선택/씬 전환으로 취소하면 원래 자리와 모델을 복구한다. 시작 건물과 신규 건물 모두 placedBuildings 사전에 정의를 등록한다. BeginMove는 기존 점유를 보존하고 원본 모델만 숨긴다. 판정 시 이동 건물 자신의 기존 칸만 제외한다. TryMove 확정 시 기존 칸을 해제하고 새 칸을 점유한다. 비용·구매 횟수·고용 해금은 변경하지 않는다. 새 스크립트 없이 BuildingPlacementController에 구현했다. 클릭 레이 선택, 겹침 거부, 취소, 이전 자리 재건설, 신규 건물 이동, 잔액 0 이동, 비활성화 취소를 메서드 호출로 검증했다.

## 2026-09-14: 자원 UI와 환전
VillageScene과 PlayScene의 Resource Bar에 벼/골드/특수 자원과 환전 버튼을 추가했다. ResourceHUD는 숫자만 갱신하며 문구는 TMP Inspector에서 편집한다. 기존 마을 정적 Rice 표시와 준비 화면 전용 숫자 갱신은 공통 HUD로 대체했다. BuildingPlacementController가 현재 세 자원을 관리하며 초기 골드/특수 자원은 0, 기존 시작 벼 설정은 유지한다. TryExchangeRice는 벼100을 골드40으로 원자적으로 환전한다. 환전 비율은 Inspector Exchange Rice Cost/Exchange Gold Gain으로 조절하며 버튼 문구도 수동 변경해야 한다. 부족한 벼나 정수 초과 시 거래하지 않는다. 환전 후 고용/건설 버튼도 잔액에 따라 갱신한다. 양쪽 씬 환전·잔액 부족·골드 유지·고용 비활성화를 검증했다.
특수 자원은 표시와 초기값 연결까지 구현했다. 보스 보상/영구 강화/새 회차 초기화/디스크 영구 저장은 아직 미구현이며, 현 상태는 동일 실행 중 씬 왕복에서만 보존된다.

## 2026-09-14: 건물 관리 메뉴 / 강화 / 철거
건물을 클릭하면 BuildingManagementUI가 열린다. 골드로 강화, 이동, 철거, 닫기 버튼이 있다. 이전의 클릭 즉시 이동은 이동 버튼으로 변경했다. ESC/우클릭/빈 바닥 클릭/씬 전환으로 메뉴를 닫는다.
BuildingPlacementController의 placedBuildings는 건물별 definition과 level(초기1)을 관리한다. TryUpgrade는 골드가 충분할 때만 비용 차감과 레벨 증가를 함께 처리한다. 이동 및 씬 왕복으로 레벨은 바뀌지 않는다. UI의 고정 문구는 Inspector, 선택한 이름/아이콘/레벨/비용만 동적으로 갱신한다.
BuildingDefinition에 upgradeGoldCost/upgradeCostMultiplier/demolitionRefundRatio를 추가했다. Farm은 80*1.5^(현재레벨-1), 다른 건물은 참고 HTML 기반의 임시 초기 강화 비용과 배율1.4를 사용한다. 철거 반환은 기본 건설비50%(Farm60), 레벨에 따른 반환 가산은 없다. 설정값은 모두 에셋 Inspector에서 조정 가능하다.
TryDemolish는 점유칸과 상태 등록을 제거하고 벼를 반환한 뒤 오브젝트를 즉시 비활성화/Destroy한다. 같은 건물의 중복 철거·강화는 거부한다. 건물 유무는 실제 남은 건물로 판정하므로 마지막 병영 철거 시 신규 병사 고용은 잠긴다. 이미 고용한 병사는 유지한다. 재건설은 Lv1이며 누적 추가 구매 횟수와 가격 배율은 철거로 되돌리지 않는다.
검증: 실제 클릭 레이로 메뉴 열기, 골드 부족, Farm 1->2->3 및 80+120골드 차감, 메뉴 이동 후 레벨 유지, 철거 환불/빈칸 재사용/중복 거부, 복수 병영 중 마지막 철거 시 해금 해제, 재건설 해금 복구, 씬 왕복 레벨 유지. 버튼 콜백과 메서드 호출 테스트이며 물리 마우스 종단 간 검증은 아니다. 최종 콘솔 오류·경고 없음.
현재 강화 범위는 개별 건물 레벨과 비용이다. 수확/Day 시스템과 전투 능력치 시스템이 아직 없으므로 생산량·전투 버프·막사 편성 확장 효과는 아직 연결하지 않았다. 앱 종료 후 레벨의 디스크 저장도 미구현이다.

## 2026-09-14: 강화 설명 / 벼 채취
건물 관리 메뉴에 8종 강화 효과 설명 TMP를 추가했다. 각 설명 문구는 씬 Inspector에서 편집하고 코드는 선택한 정의에 맞는 텍스트 오브젝트만 켠다.
RiceHarvest는 VillageScene > Building UI에 있으며 좌상단 Rice Harvest Panel의 Day/이번 채취량/남은 횟수/남은 수확량과 채취 버튼을 관리한다. Day1 총100을 25씩4회 지급, 마지막 회차에 나눗셈 나머지 지급, 소진 시 버튼 잠금이다. 기존 ResourceHUD에도 실제 지급이 반영된다.
BuildingDefinition의 initialDailyRice/additionalDailyRice/dailyRicePerUpgrade로 생산 기여량을 설정한다. Farm만100/40/20, 다른 건물은0. 현재 건물의 기여량은 BuildingPlacementController.GetDailyHarvestTotal이 합산한다. 시작 Farm의 기본100은 한 번만 포함하고 추가 Farm은40씩, 강화는 레벨당20씩 추가된다. 시작 논이 사라지면 다음 Day부터 그 논의 기여량도 빠진다.
RiceHarvest.BeginDay(day)는 다음 날짜일 때만 일일 총량과4회를 확정한다. 당일 건설/강화/철거/마을 왕복으로 다시 계산하지 않는다. 전날 미사용 횟수·수확량은 이월하지 않고 보유 벼는 유지한다. 전장 클리어 시스템은 아직 없으므로 실제 Day 진행 연결은 추후 필요하다. 앱 종료 후 저장/불러오기 연결도 아직 없다.
검증: 25지급/3회75남음, 추가 논과 강화 후 당일100유지·다음날160, 씬 왕복 유지, 4회/초과클릭 차단, 철거 당일고정·다음날반영, 101을25/25/25/26 지급, 정수 초과 시 횟수 유지, 콘솔 오류 없음. 테스트 상태는 플레이 종료로 제거했다. 이제 논 강화의 수확량 효과는 연결되었으며 다른 건물의 전투/편성 효과는 여전히 미구현이다.
