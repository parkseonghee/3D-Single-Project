# Run 진입과 전술 (2026-09-14)

> 2026-09-19: DayController/DaySettings로 시간 클리어·보스 Day·결과 보상·다음 날 귀환을 연결했다. 아래의 클리어/Day 미구현 설명은 `Docs/DaySystem.md`로 대체한다.

VillageScene의 준비 → PlayScene에서 고용 → 화면 아래 중앙의 게임 시작 순서다.
시작하면 고용·마을 복귀·환전 UI를 숨기고 전술 UI와 경과 시간을 표시한다.
WASD/방향키로 지휘관을 이동한다. 고용한 병력은 지휘관 주변의 원형 자리를 따라간다.
전술 버튼 또는 Z/X/C로 진형을 바꾼다. 기본은 밀집이다.

| 전술 | 키 | 반경 | 이동 배율 | 공격 배율* | 받는 피해 배율* | 병력 경험치 수집* |
|---|---|---:|---:|---:|---:|---|
| 밀집 | Z | 2.6 | 1.10 | 0.95 | 0.75 | 아니오 |
| 전개 | X | 5.0 | 1.00 | 1.24 | 1.08 | 아니오 |
| 산개 | C | 7.8 | 1.06 | 1.00 | 1.00 | 예 |

비율은 참고 ExgameBackUp.html의 FORMS를 따랐다. 반경은 Unity 모델 크기에 맞춘 임시값이다.
별표 항목은 설정만 준비했으며 실제 전투 적용은 아직 없다. 적·공격·피해·경험치 병·지휘관 보호/어그로 로직은 구현되지 않았다.
경과 시간은 표시용이며 생존 제한 시간, 클리어, 보상, 다음 Day 갱신을 발생시키지 않는다.
현재 준비로 돌아가기는 같은 날의 준비 상태로 복귀하는 기능이며 전장 클리어가 아니다.

## 코드와 Inspector

- `Assets/Scripts/Army/RunController.cs`: 시작/준비 상태, 전술 설정과 선택, 지휘관 이동, 병력 추종, 카메라, 시간 표시.
- `RecruitmentController.cs`: Run 중 TryHire/Back 거부. FinishAppearances로 고용 직후 시작해도 정상 크기 보장.
- `Assets/Animations/Army/*Idle.controller`: 기존 Idle에 Run 상태와 Moving bool 전환 추가. 원본 에셋은 수정하지 않음.
- PlayScene → Recruitment System → Run Controller에서 반경, 이동속도, 전술 수치, UI 연결을 수정한다.
- PlayScene → Recruitment UI → Start Run Button / Run UI에서 TMP 고정 문구를 직접 편집한다. 코드는 시간 숫자만 갱신한다.
- Formation Ring은 지휘관 중심의 전술 반경을 표시한다. 가장 큰 반경만큼 지휘관의 이동 여유를 확보해 모든 병력이 땅 안에 남는다.

고용한 인스턴스를 그대로 사용한다. 준비 복귀 시 시작 전 위치·회전·카메라를 복원하며 병력과 자원은 유지된다.
시작 버튼 중복 호출은 무시한다. 실행 상태는 디스크에 저장하지 않는다.

## 확인

Unity Play 모드에서 실제 고용/시작/전술/복귀 버튼 콜백 및 이동 Tick을 호출했다.
3명·5명의 전술 반경, 지휘관 이동, 땅 경계, Run 중 고용 거부, 중복 시작 거부, 등장 직후 크기,
준비 복귀 시 병력 수와 카메라 복원, 화면 캡처를 확인했다. 콘솔 오류·경고는 없었다.
비활성·일시정지 에디터에서 합성 키 입력은 wasPressedThisFrame을 재현하지 못해 단축키 종단 간 검증은 미완료다.
실제 Game 뷰에서 WASD와 Z/X/C를 누르는 사용자 입력 검증은 별도로 필요하다.
